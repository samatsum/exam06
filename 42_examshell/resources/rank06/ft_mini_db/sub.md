* **課題名**: `mini_db`
* **提出予定ファイル**: `*.cpp`, `*.hpp`

---

## 概要

引数としてポート番号（port）とファイルパス（path）を受け取るプログラムを作成してください。
プログラムは `127.0.0.1` の指定されたポートでクライアントの接続を待ち受け（リッスン）なければなりません。

プログラムが受信接続を受け入れる準備ができたとき、標準出力に `"ready\n"` を出力します。
プログラムは接続されたクライアントからコマンドを受信し、キーと値（key-value）のデータベースを維持します。

接続は**永続的（persistent）**です。つまり、クライアントプログラムは単一のセッション内で複数のコマンドを送信できます。

## コマンド仕様

以下のコマンドを実装してください：

### POST
* **構文**: `POST <key> <value>`
* **説明**: データベースにエントリを追加する
* **戻り値**: `"0"`

### GET
* **構文**: `GET <key>`
* **説明**: データベースからエントリを取得する
* **戻り値**: `"0 <value>"` または、キーが存在しない場合は `"1"`

### DELETE
* **構文**: `DELETE <key>`
* **説明**: データベースのエントリを削除する
* **戻り値**: キーが正常に削除された場合は `"0"`、キーが存在しない場合は `"1"`

---

* コマンドが認識されない場合、プログラムは `"2"` と応答しなければなりません。
* キーと値は任意のサイズであり、空白文字を含みませんが、リクエストのサイズが **1000文字を超えることは決してありません**。
* プログラムは**効率的**でなければなりません。

## データの永続性 (Data persistence)

プログラムが `SIGINT` シグナルを受信したとき、現在のデータベース（すなわち、すべてのキーと値のペア）を引数として与えられたファイルパスに保存し、終了（exit）しなければなりません。
プログラムが起動するたびに、このファイルの存在を確認し、存在すればそれを読み込みます。

* **ヒント**: プログラムのテストには `nc` を使用できます。

ネットワークの仕組みを忘れてしまった場合のために、いくつかのネットワークコードを含むファイルがこのディレクトリに用意されています。

## 実行例

```bash
$> ./mini_db 1111 .save &
$> nc localhost 1111 | cat -e
POST A B
0$
POST B C
0$
GET A
0 B$
GET C
1$
DELETE A
0$
DELETE C
1$
UNKNOWN_COMMAND
2$
^C
$> pkill -SIGINT mini_db
$> ./mini_db 1111 .save &
$> echo "GET B" | nc localhost 1111 | cat -e
0 C$

###########################
この課題が求めているのは、
「メモリ上で高速に動作し、かつ不意の終了時にもデータを失わない、TCP通信ベースの簡易データベースサーバー（KVS）をゼロから構築すること」
です。

## フェーズ1：サーバーの起動とクライアントの接続
# ポート1111、保存先ファイル.saveを指定して mini_db サーバーをバックグラウンド（&）で起動
# この時点では内部のデータベース（std::map）は空
$> ./mini_db 1111 .save &
# nc（netcatコマンド）を使ってサーバーにTCP接続
$> nc localhost 1111 | cat -e

## フェーズ2：永続的な接続によるデータ操作（インメモリ処理）
# サーバーは接続を維持し、連続してコマンドを受け付けます。
# すべてメモリ上（std::map）で処理されるため、この時点ではまだファイル（.save）には書き込まれていません。
# キーAに値Bを保存
POST A B
0$ # 成功
# キーBに値Cを保存
POST B C
0$ # 成功

# キーAを検索すると存在するため 0 B\n を返します。
GET A
0 B$

# キーCは存在しないため、エラーコード 1\n を返します。
GET C
1$
# キーAを削除しmasu.
DELETE A
0$ #　成功

# キーCの削除をします
DELETE C
# 失敗（キーCは存在しないので）
1$
# 内部状態: サーバーの std::map は { {"B", "C"} } になります。

# 未知のコマンドが来た場合は、不正なリクエストとして 2\n を返して弾きます。
UNKNOWN_COMMAND
2$

#この課題の最も重要な「堅牢性」のテスト
# ^C で nc（クライアント）を終了させた後、pkill を使って mini_db サーバーに対して強制終了のシグナル（SIGINT）を送ります。
# 裏側で起きていること: サーバーはただ死ぬのではなく、シグナルを検知（トラップ）し、
# 終了する直前に現在のメモリ状態 { {"B", "C"} } を .save ファイルに書き出してから安全に終了しなければなりません。
^C
$> pkill -SIGINT mini_db

# サーバーを再起動
$> ./mini_db 1111 .save &
# GET B を要求
# 裏側で起きていること: 再起動時、サーバーは起動引数に .save があるのを見てファイルを読み込み、
# メモリ上の std::map に { {"B", "C"} } を復元します。その結果、前回起動時のデータである C が正しく返却（0 C$）されました。
$> echo "GET B" | nc localhost 1111 | cat -e
0 C$

この課題を通じてあなたが証明しなければならないのは、以下の3つのレイヤーを連携させる能力です。

ネットワーク層: TCPソケットと select() を使い、複数のクライアントがいつ送ってくるか分からない文字列を、ブロックさせずに処理する能力。

データ構造層: 送られてきた文字列を正しくパースし、メモリ（std::map）上でバグなく高速に状態を管理する能力。

システム・ファイル層: OSからのシグナル（SIGINT）を割り込み処理として受け取り、メモリ上のデータをファイルに書き出して（シリアライズ）、次回起動時に読み込む（デシリアライズ）能力。

DataBaseー＞Socketー＞Server　の順番で実装＆テストをすると良いだろう。
